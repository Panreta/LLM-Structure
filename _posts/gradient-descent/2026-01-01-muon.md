Adam treats every parameter as its own coordinate. But most weights in a network are matrices, and Muon (Jordan et al., 2024) uses that. For a weight matrix $$W$$ with gradient $$G_k$$ it keeps momentum $$M_k = \beta M_{k-1} + G_k$$, then orthogonalizes the update. If

$$G_k + \beta M_k = U \Sigma V^\top$$

is a singular value decomposition, Muon steps along $$U V^\top$$: the same directions with every singular value set to 1. Rare directions get as much push as dominant ones, regardless of how the matrix is rotated. That is the fix RMSProp could only make along the axes.

An SVD is too slow to run every step, so Muon uses five Newton–Schulz iterations, $$X \leftarrow aX + b(XX^\top)X + c(XX^\top)^2X$$ with $$(a, b, c) = (3.4445,\ -4.7750,\ 2.0315)$$. They need only matrix multiplications and push every singular value close to 1.

In this 2-D figure the parameter is read as the diagonal matrix $$\mathrm{diag}(x_1, x_2)$$. Its singular directions are the axes, so orthogonalizing gives roughly the sign of each momentum entry, and every step has about the same length $$\eta$$. The path moves diagonally, with equal steps in both coordinates, and then hovers around $$\mathbf{x}^\star$$, because constant-size steps cannot settle. Real training decays $$\eta$$ toward 0 at the end for this reason. The dashed path is Adam.

Muon is applied to the hidden weight matrices; embeddings and the output layer stay on AdamW. It has trained language models with noticeably fewer steps than AdamW.
